This is my proposed frontend curriculum for Catalyst. One idea runs through it: students don't just learn to write frontend, they learn to architect it and to work with AI — and every week they ship something live. It's anchored to a real reference app, CommerceOS, that I built.

Philosophy

Build-first: introduce theory exactly when the project needs it. One capstone extended each week, so students watch real architecture evolve. AI woven in, but fundamentals before shortcuts. Deploy on Vercel from week one.

Who it's for

Already past the basics

Students arrive with programming foundations + basic frontend. We skip syntax and go deep on architecture and AI.

AssumedJS · HTML/CSS · Git · a simple UI
We ramp fastTypeScript · React at depth
We go deeparchitecture · AI features · scale
Prerequisites

Every enrolled student has passed programming foundations + has basic frontend. So we don't teach "what is a variable" — we ramp TypeScript/React quickly and spend the real time on architecture and AI.

The two spines

Every week touches both

🏛 Software Architecturecomponents → state → modular monolith → monorepo → micro-frontends · enforced boundaries
🤖 AI in Modern Frontendcoding with AI (Cursor/Claude) + building AI features (streaming, tools, RAG)

AI makes building cheap → architectural judgment is the high-value skill.

The spines

Two threads run through all 12 weeks. Architecture: how to structure and scale. AI: two layers — coding faster with AI tools, and building AI-powered features. The punchline students leave with: AI can build the structure, but deciding where the boundary goes stays human.

Format

12 weeks · two phases

One live session every week, both phases.

Cadence

Front-loaded: Phase 1 is intensive, 5–8 hours of work per week plus a live session. Phase 2 lightens to 2–3 hours of recorded content plus a live session, while the capstone is built. Every week has one live session.

The roadmap

Twelve weeks, one arc

The architecture journey is the syllabus: monolith → monorepo → micro-frontends.

Roadmap

The 12 weeks follow the exact architecture arc from my reference repo. Modular monolith in week 5, monorepo in week 7, micro-frontends in week 8, AI features in week 9, capstone weeks 11–12.

Phase 1 · Weeks 1–6

Foundations → Modular Monolith

  • W1 — TypeScript for architecture + AI workflow Cursor / Claude · read-before-accept
  • W2 — React at depth render model · hooks · reconciliation
  • W3 — Component architecture + design system the ui package
  • W4 — State architecture server vs client · React Query + Zustand
  • W5 — Modular monolith + DDD boundaries subdomains · eslint-plugin-boundaries · Dependency Cruiser
  • W6 — Rendering architecture Next.js App Router + RSC
Phase 1

Ramp fast, then land the modular monolith with enforced boundaries in week 5 — the heart of the course. Every week ships a piece of the growing CommerceOS-style app.

Phase 2 · Weeks 7–12

Monorepo → Micro-Frontends → Ship

  • W7 — Monorepo + Turborepo apps / packages · tags · caching
  • W8 — Micro-frontends + Module Federation host / remotes · React singleton · lazy + Suspense
  • W9 — AI features in the frontend Vercel AI SDK · streaming chat · tool calling
  • W10 — Quality architecture testing · a11y · Core Web Vitals
  • W11–12 — Capstone: build, deploy & defend an AI-powered app, scaled with enforced boundaries
Phase 2

Scale the app the way seniors do — monorepo, then micro-frontends — then add a real AI feature, harden quality, and finish with a defended capstone.

Architecture spine

Students don't learn these as separate topics — they scale ONE app through all three, with the boundary checks passing in CI at every stage. Same journey as the reference repo.

The AI spine

Two layers of AI

Code with AIevery week · Cursor/Claude · read-before-accept · boundary rules as guardrails
Build AI featuresW9 · streaming chat · tool calling · structured output · non-deterministic UX

Signature exercise: build a feature with and without AI, then compare speed & quality.

AI spine

Layer one runs all term: use AI to move faster without skipping fundamentals; the architecture boundary rules become the guardrails agents hit. Layer two is a dedicated week building a real AI feature with the Vercel AI SDK.
