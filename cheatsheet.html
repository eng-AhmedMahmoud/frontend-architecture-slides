Frontend Architecture — Private Speaker Cheat-Sheet

26 slides · CommerceOS · ~30 min
Thesis: trade complexity for scalability → pick the least-worst fit. Increase modularity BEFORE distributing. Move up only when growing pains force it.
1
Title — CommerceOS
"We architect frontend, not just write it. One app, monolith → micro-frontends."
2
Big idea
Every step up in scale costs complexity. No "best" — least-worst fit.
3
What is architecture
Decisions to organize a system for the qualities you want. Drivers: goals / qualities / constraints. Biggest = team size.
4
4 pillars (RPG)
Style · Characteristics · Decisions · Components. Score each stage.
5
Journey
Monolith → Monorepo → MFE, by team growth. Monorepo is a helper, not a style.
6
CommerceOS + C4
React/TanStack/Vite. C4 = Context→Container→Component→Code.
7
Monolith
Right default. Weak stat = scalability. Problem = unstructured monolith.
8
Big ball of mud
Shared order-line-items table breaks customers app; tooltip-on-timeout hides it from tests.
9
The trap 🔑
2 axes: deploy units × modularity. Units without modularity = distributed monolith. Modularity FIRST.
10
Modular monolith + DDD
Subdomains → modules. Core (orders/catalog), supporting (inventory/customers/analytics), generic (auth). Consistency > perfect.
11
Organization + encapsulation
Folders are half. Encapsulation (deps point down, no sibling imports) is the other half — must be enforced.
12
Enforce in CI
eslint-plugin-boundaries, default:disallow, capture moduleName, allow types, auth exception → sibling import fails CI. + Dependency Cruiser.
13
Monorepo (Triple-M)
3 steps: workspace→packages→tooling. app-shell + app/module + packages(ui/shared/tooling). exports = interface. One build.
14
Turborepo
Cache (9s→18ms) + orchestration (dependsOn ^build, outputs). Tags deny platform→module; catches cycles.
15
Where monorepo stops
Remaining pains: release queue (15-min build, one at a time) + no runtime component sharing.
16
When MFE
Independent deploys / diverging drivers. Vertical (route) vs horizontal (view part). Adopt when coordination cost > distribution cost.
17
Flavors + cheat
iframes / web components / Module Federation. Vertical→DIY proxy · isolation→iframes · Next→multi-zones · else→Module Federation.
18
Module Federation
Host loads remotes via remoteEntry.js; React singleton (context). lazy+Suspense+ErrorBoundary; don't forget await. Cross-framework → migration.
19
Keep decoupled
Component=reuse, MFE=independence → few props. Nanostores: expose a listener, not the atom. MF2.0 auto-types + mf-manifest.json = discovery.
20
The cost
CSS conflicts → Tailwind (atomic). Dup deps, version skew, many pipelines. Adopt via cost analysis.
21
Decision framework
Match pattern to pain. Modularity before distribution. Smallest fix wins. (pause — photo slide)
22
Architecture & AI
Fundamentals matter MORE. Docs/boundaries = context; lint = guardrails. Just-enough architecture, not full spec-driven.
23
Reference impl (diagram)
All 3 stages in one repo: app-shell host + catalog/orders (build-time) + analytics remote (Module Federation) over the platform layer. Boundaries enforced 3 ways ✓.
24
Explore the code (2 repos)
Index + C4 diagrams v1→v3: github.com/eng-AhmedMahmoud/frontend-architecture. Implementation (installs/builds/boundaries pass): …/commerceos-frontend-architecture.
25
Recap
Six lines — decisions / pillars / modular monolith / monorepo / MFE / match-the-pain.
26
Close — their turn
"6-person startup wants MFE 'to scale' — your call?" Let them answer → modular monolith, earn MFE later. "Questions?"

Decision cheat

  • Messy app, 1 team → modular monolith
  • Apps share code → monorepo
  • Teams blocked on deploys → micro-frontends
  • Always: modularity before distribution
